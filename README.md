# egais-v.0.1 — генерация актов списания и переноса остатков ЕГАИС

Настольная программа для Windows x64: формирует акты списания по крепкому алкоголю
и пиву, а также документ переноса остатков в магазин (`TransferToShop`) на основании
выгрузок текущих остатков из ЕГАИС.

Программа работает в двух режимах, которые **несовместимы**: при выборе режима
переноса поля актов списания скрываются и деактивируются, и наоборот.

## Что делает программа

### Режим «Акты списания»

1. Читает файл выгрузки остатков (`ReplyRests_v2.xml`).
2. Делит позиции на две группы по коду вида продукции
   (`pref:ProductVCode`):
   * **крепкий алкоголь** — все коды, кроме перечисленных в `Constants.ALLOWED_PRODUCT_CODES`;
   * **пиво и пивные напитки** — коды `500`, `510`, `520`, `263`, `261`, `262`.

   ```
   ns:Documents [Version=1.0]
   ├── ns:Owner
   │   └── ns:FSRAR_ID        код организации
   └── ns:Document
       └── ns:ActWriteOff_v3
           ├── awr:Identity   номер акта
           ├── awr:Header
           │   ├── awr:ActNumber      номер акта
           │   ├── awr:ActDate        дата списания (ГГГГ-ММ-ДД)
           │   ├── awr:TypeWriteOff   причина списания
           │   └── awr:Note           примечание
           └── awr:Content    позиции с марками
   ```
//TODO скорректировать названия
4. Записывает в выбранную папку:
   * `ActWriteOffStrong.xml` — акт по крепкому алкоголю (с марками `ce:amc`);
   * `ActWriteOffBeer.xml` — акт по пиву.

### Режим «Перенос остатков в магазин»

1. Читает выгрузку остатков магазина (`ReplyRestsShop_v2.xml`) и находит позиции
   `rst:ShopPosition` с **отрицательным** количеством.
2. Запоминает код продукции (`pref:AlcCode`) и количество без знака «минус».
3. Читает выгрузку остатков склада (`ReplyRests_v2.xml`) и отбирает позиции
   `rst:StockPosition`, у которых совпал код продукции **и** количество.
4. Оборачивает найденные позиции в документ переноса:

   ```
   ns:Documents [Version=1.0]
   ├── ns:Owner
   │   └── ns:FSRAR_ID        код организации
   └── ns:Document
       └── ns:TransferToShop
           ├── tts:Identity   Identity документа
           ├── tts:Header
           │   ├── tts:TransferNumber  номер переноса
           │   └── tts:TransferDate    дата переноса (ГГГГ-ММ-ДД)
           └── tts:Content    позиции
               └── tts:Position
                   ├── tts:Identity     номер позиции в выгрузке склада
                   ├── tts:ProductCode  код продукции
                   ├── tts:Quantity     количество
                   └── tts:InformF2
                       └── pref:F2RegId номер справки 2
   ```

5. Записывает в выбранную папку `TransferToShop.xml`.

## Данные акта списания

Эти значения одинаковы для всех позиций документа и задаются в окне программы
(или аргументами командной строки):

| Поле | Тег в документе | По умолчанию |
|---|---|---|
| FSRAR_ID организации | `ns:Owner/ns:FSRAR_ID` | берётся из файла остатков (поле только для чтения) |
| Номер акта | `awr:ActNumber` и `awr:Identity` | — (заполняется вручную) |
| Дата списания | `awr:ActDate` | сегодняшняя дата |
| Причина списания | `awr:TypeWriteOff` | `Порча` |
| Примечание | `awr:Note` | `Списание по инвентаризации 1 от <ДД-ММ-ГГГГ>` |

Дата вводится как `ДД-ММ-ГГГГ` (принимается и `ГГГГ-ММ-ДД`), а в документе
всегда записывается в формате ЕГАИС — `ГГГГ-ММ-ДД`. Если поля «Причина списания»
или «Примечание» оставить пустыми, соответствующие теги в акт не попадут.

## Данные документа переноса

| Поле | Тег в документе | По умолчанию |
|---|---|---|
| FSRAR_ID организации | `ns:Owner/ns:FSRAR_ID` | берётся из файла остатков магазина (поле только для чтения) |
| Identity документа | `tts:Identity` | если пусто — подставляется номер переноса |
| Номер переноса | `tts:TransferNumber` | — (запоминается между запусками) |
| Дата переноса | `tts:TransferDate` | сегодняшняя дата |

Дата вводится так же, как в акте: `ДД-ММ-ГГГГ` (принимается и `ГГГГ-ММ-ДД`),
а в документе записывается `ГГГГ-ММ-ДД`. FSRAR_ID берётся из файла остатков
магазина, а если там его нет — из файла остатков склада.

## Возможности интерфейса

* выбор режима работы: «Акты списания» или «Перенос остатков в магазин»; при смене
  режима поля другого режима скрываются и деактивируются, а кнопка формирования
  меняет надпись; выбранный режим запоминается;
* выбор файла остатков (`*.xml`) через диалог или перетаскиванием файла в окно;
* в режиме переноса — выбор двух файлов: остатков магазина
  (`ReplyRestsShop_v2.xml`) и остатков склада (`ReplyRests_v2.xml`); при
  перетаскивании два файла подряд попадают в эти поля по очереди;
* выбор папки для сохранения результата (общая для обоих режимов);
* ввод данных акта: номер, дата, причина и примечание;
* FSRAR_ID организации подставляется из выбранного файла остатков: поле не
  редактируется, а при выборе другого файла значение заменяется (если кода в файле
  нет — поле очищается и об этом сообщается в журнале);
* выбор, какие акты формировать: крепкий алкоголь, пиво или оба;
* журнал работы с отметками времени и понятными сообщениями об ошибках;
* кнопка «Открыть папку» для перехода к результату;
* отправка готового документа в УТМ: поле «Адрес УТМ» (предзаполнено
  `http://localhost:8080`) и кнопка «Отправить в УТМ»; тип документа зависит
  от режима;
* запоминание последних путей, номера акта, причины списания, номера и Identity
  переноса и выбранного режима;
* формирование выполняется в фоновом потоке — окно не «зависает».

## Требования

| Что нужно | Версия |
|---|---|
| Windows | x64, Windows 10 и новее |
| JDK для сборки | 17 (подойдёт и 11, но тогда не соберётся `.exe` — нужен `jpackage`) |
| Java для запуска `.jar` | 11 и новее |

Готовый `EgaisWriteOff.exe` встроенную среду выполнения содержит сам — Java на
машине пользователя не требуется.

## Сборка

Самый простой способ — `build.cmd` (он сам обходит запрет на выполнение `.ps1`,
который часто включён в Windows по умолчанию):

```bat
cd C:\Users\Admin\IdeaProjects\egais-v.0.1
build.cmd
```

Либо тот же скрипт напрямую, если политика выполнения позволяет:

```powershell
cd C:\Users\Admin\IdeaProjects\egais-v.0.1
.\build.ps1
# если появляется «выполнение сценариев отключено»:
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт компилирует исходники, собирает jar и создаёт приложение:

```
build\egais-writeoff.jar          — исполняемый jar
dist\EgaisWriteOff\EgaisWriteOff.exe  — готовая программа для Windows
```

Полезные параметры:

```powershell
.\build.ps1 -SkipPackage          # только jar, без exe
.\build.ps1 -JdkHome 'C:\path\to\jdk-17'
.\build.ps1 -AppVersion 1.1
```

Если JDK не указан, скрипт ищет его в `JAVA_HOME` и в `%USERPROFILE%\.jdks`.

Альтернативная сборка через Maven (даёт только jar):

```powershell
mvn package
java -jar target\egais-writeoff.jar
```

## Запуск

**Графический интерфейс**

```
dist\EgaisWriteOff\EgaisWriteOff.exe
```

или

```powershell
java -jar build\egais-writeoff.jar
```

**Консольный режим** (для пакетной обработки и запуска по расписанию)

```powershell
java -jar build\egais-writeoff.jar --in ReplyRests_v2.xml --out C:\Acts --number 10 --strong --beer
```

| Аргумент | Назначение |
|---|---|
| `--in <файл>` | выгрузка остатков ЕГАИС |
| `--out <папка>` | папка для актов списания |
| `--number <номер>` | номер акта (обязателен) |
| `--fsrar-id <код>` | FSRAR_ID организации; если не указан, берётся из файла остатков |
| `--date <ДД-ММ-ГГГГ>` | дата списания, по умолчанию — сегодняшняя |
| `--type <причина>` | причина списания, по умолчанию — `Порча` |
| `--note <текст>` | примечание, по умолчанию — `Списание по инвентаризации 1 от <сегодня>` |
| `--strong` | только акт по крепкому алкоголю |
| `--beer` | только акт по пиву |
| `--help` | подсказка |

Если не указан ни `--strong`, ни `--beer`, формируются оба акта.
Коды возврата: `0` — успех, `1` — ошибка данных, `2` — неверные аргументы.

## Отправка в УТМ

Готовый документ можно отправить в УТМ (универсальный транспортный модуль) прямо из
окна программы: для этого служат поле **«Адрес УТМ»** и кнопка **«Отправить в УТМ»**.

* поле предзаполнено значением `http://localhost:8080`, введённый адрес запоминается;
* путь приёма дописывается к адресу автоматически, если его ещё нет; если схема не
  указана, подставляется `http://`;
* тип документа зависит от выбранного режима:
  * акты списания — `/opt/in/ActWriteOff_v3` (по одной команде `curl` на каждый акт);
  * перенос остатков в магазин — `/opt/in/TransferToShop`;
* отправка выполняется утилитой `curl`:

  ```
  curl -F "xml_file=@client.xml" http://localhost:8080/opt/in/ActWriteOff_v3
  curl -F "xml_file=@client.xml" http://localhost:8080/opt/in/TransferToShop
  ```

* файлы результата не меняются: документ копируется во временный каталог под именем
  `client.xml` и передаётся уже оттуда (УТМ ожидает именно это имя файла);
* ответ УТМ — квитанция или текст ошибки — выводится в журнал работы;
* если программа только запущена, а документ уже лежит в папке результата, перед
  отправкой выводится подтверждение со списком файлов: так документ от другой
  организации или другой даты не уйдёт в УТМ случайно.

Отправка идёт в фоновом потоке и прекращается по таймауту (60 секунд), поэтому
зависший УТМ не блокирует окно.

### О коде возврата curl

Команда запускается без ключа `--fail`: код возврата `0` означает, что запрос ушёл
и УТМ ответил, а решение о приёме документа содержится в самом ответе. Поэтому
программа показывает ответ УТМ в журнале, а вывод о приёме не делает только по коду
возврата. Если ключ `--fail` нужен, его легко добавить в `core/UtmSender.java`.

## Ограничения

* разбор опирается на префиксы тегов `rst:` и `pref:` — выгрузка должна быть
  в том виде, в каком её отдаёт ЕГАИС;
* серединная часть марки (`Constants.MID_MARK`) зафиксирована в коде, как и в
  исходной версии;
* данные шапки общие для обоих актов: отдельные номер и дату для пива и крепкого
  алкоголя задать нельзя;
* в режиме переноса количество на складе сравнивается с количеством в магазине
  допуска по количеству нет;
* для отправки в УТМ нужна утилита `curl`: в Windows 10 и новее она входит в
  состав системы (`%SystemRoot%\System32\curl.exe`).
