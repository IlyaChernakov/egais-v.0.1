# egais-v.0.1 — генерация актов списания ЕГАИС

Настольная программа для Windows x64: формирует акты списания по крепкому алкоголю
и пиву на основании выгрузки текущих остатков из ЕГАИС.

## Что делает программа

1. Читает файл выгрузки остатков (`ReplyRests_v2.xml`).
2. Делит позиции на две группы по коду вида продукции
   (`pref:ProductVCode`):
   * **крепкий алкоголь** — все коды, кроме перечисленных в `Constants.ALLOWED_PRODUCT_CODES`;
   * **пиво и пивные напитки** — коды `500`, `510`, `520`, `263`, `261`, `262`.
3. Оборачивает позиции в полный документ акта списания — как в образце
   `src/main/java/files/1.xml`:

   ```
   ns:Documents [Version=1.0]
   ├── ns:Owner
   │   └── ns:FSRAR_ID        код организации
   └── ns:Document
       └── ns:ActWriteOff_v3
           ├── awr:Identity   номер акта
           ├── awr:Header
           │   ├── awr:ActNumber      номер акта
           │   ├── awr:ActDate        дата списания (ГГГГ-ММ-ДД)
           │   ├── awr:TypeWriteOff   причина списания
           │   └── awr:Note           примечание
           └── awr:Content    позиции с марками
   ```

4. Записывает в выбранную папку:
   * `ActWriteOffStrong.xml` — акт по крепкому алкоголю (с марками `ce:amc`);
   * `ActWriteOffBeer.xml` — акт по пиву.

Состав и порядок элементов соответствуют образцу `src/main/java/files/1.xml`:
при тех же данных акта документ отличается только отступами и местом объявления
пространства имён `ce` — см. «Ограничения».

## Данные акта

Эти значения одинаковы для всех позиций документа и задаются в окне программы
(или аргументами командной строки):

| Поле | Тег в документе | По умолчанию |
|---|---|---|
| FSRAR_ID организации | `ns:Owner/ns:FSRAR_ID` | берётся из файла остатков (поле только для чтения) |
| Номер акта | `awr:ActNumber` и `awr:Identity` | — (заполняется вручную) |
| Дата списания | `awr:ActDate` | сегодняшняя дата |
| Причина списания | `awr:TypeWriteOff` | `Порча` |
| Примечание | `awr:Note` | `Списание по инвентаризации 1 от <ДД-ММ-ГГГГ>` |

Дата вводится как `ДД-ММ-ГГГГ` (принимается и `ГГГГ-ММ-ДД`), а в документе
всегда записывается в формате ЕГАИС — `ГГГГ-ММ-ДД`. Если поля «Причина списания»
или «Примечание» оставить пустыми, соответствующие теги в акт не попадут.

## Возможности интерфейса

* выбор файла остатков (`*.xml`) через диалог или перетаскиванием файла в окно;
* выбор папки для сохранения результата;
* ввод данных акта: номер, дата, причина и примечание;
* FSRAR_ID организации подставляется из выбранного файла остатков: поле не
  редактируется, а при выборе другого файла значение заменяется (если кода в файле
  нет — поле очищается и об этом сообщается в журнале);
* выбор, какие акты формировать: крепкий алкоголь, пиво или оба;
* журнал работы с отметками времени и понятными сообщениями об ошибках;
* кнопка «Открыть папку» для перехода к результату;
* запоминание последних путей, номера акта и причины списания;
* формирование выполняется в фоновом потоке — окно не «зависает».

## Требования

| Что нужно | Версия |
|---|---|
| Windows | x64, Windows 10 и новее |
| JDK для сборки | 17 (подойдёт и 11, но тогда не соберётся `.exe` — нужен `jpackage`) |
| Java для запуска `.jar` | 11 и новее |

Готовый `EgaisWriteOff.exe` встроенную среду выполнения содержит сам — Java на
машине пользователя не требуется.

## Сборка

Самый простой способ — `build.cmd` (он сам обходит запрет на выполнение `.ps1`,
который часто включён в Windows по умолчанию):

```bat
cd C:\Users\Admin\IdeaProjects\egais-v.0.1
build.cmd
```

Либо тот же скрипт напрямую, если политика выполнения позволяет:

```powershell
cd C:\Users\Admin\IdeaProjects\egais-v.0.1
.\build.ps1
# если появляется «выполнение сценариев отключено»:
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт компилирует исходники, собирает jar и создаёт приложение:

```
build\egais-writeoff.jar          — исполняемый jar
dist\EgaisWriteOff\EgaisWriteOff.exe  — готовая программа для Windows
```

Полезные параметры:

```powershell
.\build.ps1 -SkipPackage          # только jar, без exe
.\build.ps1 -JdkHome 'C:\path\to\jdk-17'
.\build.ps1 -AppVersion 1.1
```

Если JDK не указан, скрипт ищет его в `JAVA_HOME` и в `%USERPROFILE%\.jdks`.

Альтернативная сборка через Maven (даёт только jar):

```powershell
mvn package
java -jar target\egais-writeoff.jar
```

## Запуск

**Графический интерфейс**

```
dist\EgaisWriteOff\EgaisWriteOff.exe
```

или

```powershell
java -jar build\egais-writeoff.jar
```

**Консольный режим** (для пакетной обработки и запуска по расписанию)

```powershell
java -jar build\egais-writeoff.jar --in ReplyRests_v2.xml --out C:\Acts --number 10 --strong --beer
```

| Аргумент | Назначение |
|---|---|
| `--in <файл>` | выгрузка остатков ЕГАИС |
| `--out <папка>` | папка для актов списания |
| `--number <номер>` | номер акта (обязателен) |
| `--fsrar-id <код>` | FSRAR_ID организации; если не указан, берётся из файла остатков |
| `--date <ДД-ММ-ГГГГ>` | дата списания, по умолчанию — сегодняшняя |
| `--type <причина>` | причина списания, по умолчанию — `Порча` |
| `--note <текст>` | примечание, по умолчанию — `Списание по инвентаризации 1 от <сегодня>` |
| `--strong` | только акт по крепкому алкоголю |
| `--beer` | только акт по пиву |
| `--help` | подсказка |

Если не указан ни `--strong`, ни `--beer`, формируются оба акта.
Коды возврата: `0` — успех, `1` — ошибка данных, `2` — неверные аргументы.

```
├── alco/strong/                     крепкий алкоголь: разбор позиций и запись акта

```

## Отличия от исходной версии

* акт формируется целиком: позиции обёрнуты в конверт `ns:Documents` с шапкой
  (`ns:Owner`, `awr:Identity`, `awr:Header`) — как в образце `files/1.xml`;
* пути к файлам больше не «зашиты» в код — они выбираются в интерфейсе;
* добавлены данные акта: FSRAR_ID, номер, дата, причина списания и примечание;
* ошибки разбора и записи показываются пользователю, а не глушатся в `printStackTrace()`;
  если в позиции нет обязательного элемента, сообщается её номер и имя тега;
* некорректный код продукции в позиции приводит к понятной ошибке вместо пустого списка;
* добавлены консольный режим, журнал работы и упаковка в `.exe`.

## Ограничения

* разбор опирается на префиксы тегов `rst:` и `pref:` — выгрузка должна быть
  в том виде, в каком её отдаёт ЕГАИС;
* серединная часть марки (`Constants.MID_MARK`) зафиксирована в коде, как и в
  исходной версии;
* пространство имён `ce` объявлено один раз в корне документа, поэтому на каждом
  `ce:amc` оно не повторяется, как в образце `1.xml`; на разбор XML это не влияет;
* данные шапки общие для обоих актов: отдельные номер и дату для пива и крепкого
  алкоголя задать нельзя.
